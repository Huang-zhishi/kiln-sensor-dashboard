# 中控台「视频监控查看」功能 · 实施计划书

> 项目：窑炉传感器中控台（kiln-sensor-dashboard）
> 目标：在中控台新增一个「监控查看」页面，支持**直播**与**历史回放**
> 状态：待网络与凭据到位后实施（见 §8 前置条件）
> 编制日期：2026-10-04

---

## 1. 背景与目标

现场已部署海康（Hikvision）视频监控系统（摄像机 + NVR），目前与工艺数据中控台相互独立。
本功能在中控台内新增统一入口，值班人员无需切换到海康客户端，即可在中控台查看重点设备**实时画面**与**历史录像**。

**需求范围（用户明确）**
- ✅ 直播查看
- ✅ 历史回放
- ❌ 云台控制、报警/智能事件联动、人脸/车牌识别、视频存储——**本期均不做**

### 2.2 网络现状（**关键约束**）

- 中控台服务器：`192.168.1.78/24`，网关 `192.168.1.1`（`enp6s0`）
- 摄像机/NVR 网段：`192.168.0.0/22`、`192.168.2.0/24`
- 实测：从服务器访问 `192.168.0.254:80/554`、`192.168.2.3:80`、`192.168.2.1` **全部不可达**；`192.168.0.0/22` 不在本机路由表
- **服务器存在第二块物理网卡 `enp5s0`，处于 DOWN（NO-CARRIER，未插网线）**——判断为预留给摄像机网段的接口

> 结论：**当前网络不满足接入条件**，需现场/网管处理（§8）。

### 2.3 浏览器播放的技术事实

- 浏览器**不能直接播放 RTSP**。
- 海康旧的 Web 插件（WebControl / NPAPI / ActiveX）在现代浏览器（尤其中控台已适配的移动端）**已废弃，不可用**。
- 因此直播与历史回放**都需要流媒体网关**将 RTSP 转封装为 HLS / WebRTC。
- 注意：部分老机型默认 **H.265**，Chrome 系浏览器不支持 HLS(HEVC)，必要时需转码为 H.264。

## 3. 总体架构

```
       浏览器（中控台 /monitor 页面，含移动端）
                    │  同源请求（凭据不出服务端）
                    ▼
       中控台 Next.js  BFF  /api/monitor/*
        · 设备/通道清单（含 ISAPI 枚举缓存）
        · 生成播放地址、按需拉起流
        · 媒体网关控制、鉴权
                    │  HTTP（内网）
                    ▼
       媒体网关（新增容器：MediaMTX / ZLMediaKit）
        · 拉取 RTSP → 转 HLS / WebRTC
        · 按需拉流（on-demand），无观看不占带宽
                    │  RTSP :554（内网）
                    ▼
       海康 NVR / 摄像机（192.168.0.x / 192.168.2.x）
        · 直播：/Streaming/Channels/{ch}01
        · 回放：/Streaming/tracks/{ch}01?starttime=…&endtime=…
```

**职责划分**
- 中控台 BFF：凭据隔离、通道清单、URL 生成、网关编排、限流。
- 媒体网关：只做拉流与转封装，无业务逻辑。
- NVR：提供直播流与录像回放流。

---

## 4. 技术选型

| 项 | 选型 | 理由 |
|----|------|------|
| 媒体网关 | **MediaMTX**（备选 ZLMediaKit） | 单二进制/单容器、配置简单、内置 HLS + WebRTC + REST API、按需拉流 |
| 传输协议 | **直播 WebRTC**（低延迟）/ **HLS**（兼容兜底）；**回放 HLS** | 回放对延迟不敏感，HLS 最省事；直播用 WebRTC 可达亚秒级 |
| 设备控制 | 海康 **ISAPI**（HTTP + Digest） | 枚举通道、通道名、快照；RTSP 用于取流 |
| 前端播放 | `hls.js`（HLS）+ 原生 `<video>`；WebRTC 用 `whep` | 无插件 |
| 凭据管理 | 服务端 `.env`，BFF 代理 | 摄像机密码不下发浏览器 |

**RTSP 地址规范（实现时以实测机型为准）**
- 直播（NVR 通道）：`rtsp://<user>:<pwd>@<nvr>:554/Streaming/Channels/<ch>01`
- 直播（摄像机直连）：`rtsp://<user>:<pwd>@<cam>:554/Streaming/Channels/101`
- 回放（NVR）：`rtsp://<user>:<pwd>@<nvr>:554/Streaming/tracks/<ch>01?starttime=<UTC>&endtime=<UTC>`
  - 时间格式 `YYYYMMDDThhmmssZ`（UTC，北京时间 = UTC+8）

## 5. 后端接口设计（BFF）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/monitor/groups` | NVR 分组 + 通道清单（ISAPI 枚举，带缓存） |
| GET | `/api/monitor/channels?nvr=&q=` | 通道列表/搜索（含通道名、在线状态） |
| POST | `/api/monitor/live` | 入参 `{cameraId}` → 拉起直播流，返回播放地址 |
| POST | `/api/monitor/playback` | 入参 `{cameraId, start, end}` → 拉起回放流，返回播放地址 |
| POST | `/api/monitor/stop` | 停止按需流，释放 NVR 连接 |
| GET | `/api/monitor/snapshot?cameraId=` | 单帧快照（列表缩略图/离线兜底） |

要点：
- 所有设备地址/凭据仅存在于服务端；返回给前端的只有**媒体网关的播放地址**。
- 网关路径按 `cameraId` 命名，支持复用（同一路多人看只拉一次）。
- 加超时、错误降级（网关不可用/设备离线返回明确状态）。

## 6. 前端页面设计（`/monitor`）

- **左栏**：按 NVR 分组的通道树（搜索、在线状态点），可选设备来自配置或 ISAPI。
- **主区**：
  - **直播**：单画面 / 2×2 / 3×3 网格；点击通道即播；WebRTC 优先，失败回退 HLS。
  - **历史回放**：选通道 + 日期时间范围 → 播放器 + 时间轴；HLS 播放。
- **入口**：中控台顶部导航新增「视频监控」（与告警中心/报表中心同级）。
- **移动端**：单列布局、单画面优先（复用已完成的移动端适配规范）。
- **明确不做**：云台、预置位、抓拍下载、多用户权限。

---

## 7. 安全

- 摄像机凭据只存服务端 `.env`（`gitignore`），浏览器不可见。
- 页面与 API 仅内网可达（沿用现有部署：Next.js 监听 `127.0.0.1`，nginx 反代）。
- 媒体网关不暴露到公网；播放地址带随机路径/短期有效期（可选）。
- 只读：不提供任何下发/控制能力。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 网络不可达（当前） | 无法实施 | P1 优先解决；网关部署在与摄像机同网段的机器作为备选 |
| 老机型仅 H.265 | Chrome 无法播 HLS | 网关按需 `ffmpeg` 转 H.264；或引导使用支持 HEVC 的浏览器 |
| NVR 并发取流上限 | 多路同时看会失败 | 按需拉流 + 复用 + 单页路数限制；必要时降低码流（子码流） |
| RTSP 回放 URL 机型差异 | 回放取不到流 | 按机型适配 URL 模板；回退 ISAPI 回放 |
| 热成像/球机通道结构不同 | 通道枚举错乱 | 用 ISAPI 逐台探测通道能力，配置化修正 |
| 网线/交换机未到位 | 阻塞 | 见 §8 P1 |
