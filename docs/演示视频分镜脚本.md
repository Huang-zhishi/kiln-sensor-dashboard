# 窑炉传感器中控台 · 3 分钟演示视频分镜脚本

> 版本：v1｜时长：3:00｜形态：屏幕录制 + 配音 + 字幕｜用途：转正答辩 / 内部评审 / 对外传播
> 主叙事：从「凌晨一次温度突破历史极值」到「自动分析 → 闭环处置 → 知识沉淀」的全链路闭环。

---

## 0. 视频定位

| 项 | 设定 |
|---|---|
| 时长 | **180 秒**（硬上限，剪不超过 3:15） |
| 受众 | 不懂底层技术的管理者/评审；工程师看细节 |
| 核心信息 | **① 异常不再靠人盯 ② 分析可自证、可闭环 ③ 经验能沉淀** |
| 风格 | 冷静、工业感、少特效；节奏前紧后松，重点段放慢 |
| 语速 | 旁白 ≈ 4.5 字/秒；全文约 750–820 字 |
| 比例 | 16:9，1920×1080；浏览器 100% 缩放，隐藏书签栏 |
| 不出现 | 密钥、内网 IP、真实人名、控制台报错、浏览器地址栏乱码 |

**一句话卖点（开场钩子）**：*“凌晨 2 点，窑炉温度悄悄突破历史极值——没人盯着屏幕，但 40 秒后，一份带处置建议的分析报告已经摆在值班员面前。”*

## 1. 录制前准备清单

- [ ] 服务健康：`docker ps` 里 `kiln-dashboard`、`sensor-monitor-agent` 均 healthy。
- [ ] 数据在线：首页有实时数据在跳，无「离线测点」红色面板（或只留 1 个做铺垫）。
- [ ] 企微推送：确认 `WECHAT_WEBHOOK_URL` 可用，群里能收到消息（提前自测一条）。
- [ ] Agent 可用：随便问一句知识库问题能返回（预热模型，避免首问慢）。
- [ ] 演示数据：提前制造 1 条「突破历史最高值」事件（见 §7 录制模式），并**保留 1 条历史“分析失败”记录**用于展示「重新分析」。
- [ ] 录屏工具：OBS / QuickTime，1080p、30fps、仅录指定窗口；鼠标指针开高亮。
- [ ] 浏览器：干净的专用窗口，只开中控台与企微两个标签；关闭通知弹窗干扰。
- [ ] 关闭无关弹窗：系统通知、微信、更新提示。
- [ ] 准备手机/企微群截图作画中画（可选）。

## 3. 逐镜脚本

### 镜头 1 ｜ 00:00–00:12（12s）钩子

- **画面**：黑底 → 中央白字 `凌晨 2:47 · 2#冷却器出口温度突破历史极值`；2 秒后右侧滑入一条企业微信告警卡片；最后切到中控台首页实况。
- **操作**：无需操作，纯剪辑。
- **旁白**：*“凌晨两点四十七分，二号冷却器出口温度悄悄冲破了历史最高值。没有人守在屏幕前——但四十秒后，一份带根因和处置建议的分析报告，已经推到了值班员手机上。”*
- **字幕**：把“没有人在盯屏”“40 秒出报告”加粗高亮。
- **拍摄要点**：开场 3 秒内必须出现“突破/告警”视觉，别放 logo 动画浪费黄金时间。

### 镜头 2 ｜ 00:12–00:30（18s）系统总览

- **画面**：中控台首页全屏。
  1. 顶部统计卡（在线测点 / 实时值 / 今日异常数）→ 鼠标扫过；
  2. 左侧「窑况总览」+「离线测点」→ 轻停 1 秒；
  3. 中间趋势曲线在动；
  4. 右侧「异常列表」滚动。
- **操作**：鼠标从左到右缓缓划过四大区块，不要快速乱晃。
- **旁白**：*“这是窑炉传感器中控台。它把全厂测点的实时数据、历史趋势、离线状态和异常事件，集中在一块屏上。数据来自 TDengine 时序库，秒级刷新。”*
- **字幕**：实时监测 / 历史趋势 / 离线感知 / 异常汇聚
- **拍摄要点**：让曲线明显“动起来”，证明是实时数据不是截图。

### 镜头 3 ｜ 00:30–00:55（25s）事件发现

- **画面**：
  1. 首页右侧异常列表出现一条红色「突破历史最高值 · 2#冷却器出口温度TI_809」；
  2. 点击进入「告警中心」→ 活动告警，红色行高亮；
  3. 右侧画中画：企业微信群弹出同一条告警（含测点、数值、方向）；可放大企微卡片 2 秒。
- **操作**：点击异常项 → 切到 `/alerts` → 悬停活动告警行。
- **旁白**：*“当任意测点突破历史极值时，系统秒级判定并推送企业微信。不用刷新、不用盯盘，异常自己会找上门。”*
- **字幕**：突破历史极值 · 秒级判定 · 企业微信直达
- **拍摄要点**：企微推送画面最好用真实群消息录屏；没有就贴一张清晰的告警卡片截图并做轻微缩放。

### 镜头 4 ｜ 00:55–01:35（40s）**核心：Agent 分析**

- **画面**：
  1. 点开该异常 → 右侧「异常详情」抽屉；
  2. 依次展示：基本信息（触发时刻 / 触发值 248.10℃ / 历史区间 0~229.20℃）、「触发前后趋势 ±30 分钟」曲线（触发点虚线标注 + 峰值 324.80℃）；
  3. 下滚到「Agent 分析」——报告正文分段展示：**结论摘要 → 异常时段及数值说明 → 可能原因 → 处理建议 → 依据来源**；
  4. 高亮报告里“多源核实”的措辞（历史数据 / 知识库 SOP / 安全联锁 / 故障影响链）。
- **操作**：缓慢下滚，在报告的 4 个小标题处各停 1 秒。
- **旁白**：*“点击异常，Agent 会在后台做一轮完整分析：它先核实历史趋势判断是真异常还是毛刺，再检索知识库里的工艺文档、安全联锁和故障影响链，最后给出一份结构化的报告——结论、可能原因、处置建议、依据来源，全都写清楚，可追溯、不编造。”*
- **字幕**：多源取证 · 结构化报告 · 依据可追溯
- **拍摄要点**：**这是全片最值钱的 40 秒**，宁可慢；报告文字要可读（可局部放大 110%）。

### 镜头 5 ｜ 01:35–01:55（20s）闭环处理

- **画面**：
  1. 抽屉内「处理闭环」表单：填处理人 → 选根因分类（如“仪表/测点异常”）→ 填处理措施 → 点「标记已处理」；
  2. 顶部出现「已处理」绿色标记；
  3. 展示下方「处理时间线」出现一条记录。
- **操作**：快速但完整地演示一次闭环提交。
- **旁白**：*“发现异常只是第一步。值班员在这里登记处理人和根因分类，形成完整的时间线——谁、在什么时候、因为什么、怎么处理的，一条不落。”*
- **字幕**：处理人 · 根因分类 · 措施 · 时间线
- **拍摄要点**：根因分类下拉展开时停半秒，让观众看清选项。

### 镜头 6 ｜ 01:55–02:15（20s）能力广度（快带）

- **画面**（每屏约 6–7 秒，快速切换）：
  1.「工艺流程」页：PFD 流程图，窑体上带“近 24h 异常 N 条”角标，工艺与异常联动；
  2.「报表中心」：选“夜班/近 7 天” → 生成测点 min/max/avg/告警次数表格 → 点「导出 CSV」；
  3.「历史查询」：选一个测点 + 时间段，趋势图秒出。
- **操作**：切页要快、干脆；每页只做一个动作。
- **旁白**：*“除了异常闭环，它还提供工艺流程与异常联动、按班次和周期的自动报表，以及任意测点的历史回查。过去要导几个 Excel 的活，现在一块屏搞定。”*
- **字幕**：工艺联动 · 周期报表 · 历史回查
- **拍摄要点**：这段是“广度”，节奏要明显加快，别停留讲解。

### 镜头 7 ｜ 02:15–02:40（25s）彩蛋：能问、能听

- **画面**：
  1. 打开「问 Agent」对话入口，输入/展示：*“回转窑结圈怎么处理？”* → 返回带文档出处（PFD/SOP）的答案；
  2. （如环境支持）切语音：对着麦克风说 *“二号冷却器现在出口温度多少？”* → 语音播报当前值。
- **操作**：问题预先准备好；若语音不稳定，改用文字问答 + 界面展示。
- **旁白**：*“它不只是看板，还是一个懂工艺的助手。你可以直接问它工艺问题，它会给出带文档出处的答案；也可以动口不动手，用语音问当前工况。”*
- **字幕**：知识库问答 · 答案有出处 · 语音问数
- **拍摄要点**：语音是加分项，**不稳定就删掉**，别为彩蛋牺牲可信度。

### 镜头 8 ｜ 02:40–03:00（20s）价值总结 + 落版

- **画面**：
  1. 回到首页总览全景；
  2. 三张数据卡依次弹出字幕：`异常发现：秒级` / `分析报告：约 40 秒` / `处置全程：可追溯`；
  3. 落版：`窑炉传感器中控台 · 智能制造全链路 Agent`。
- **旁白**：*“从秒级发现，到自动分析，再到闭环沉淀——让每一条异常都有结论、有依据、有交代。这就是窑炉传感器中控台，和它背后的智能制造全链路 Agent。”*
- **字幕**：发现 · 分析 · 闭环 · 沉淀
- **拍摄要点**：最后 3 秒留白放 logo/落版，不要有旁白。

## 4. 旁白纯文稿（配音员/字幕用）

> 全片约 780 字，按 4.5 字/秒 ≈ 2 分 55 秒，留 5 秒气口。

凌晨两点四十七分，二号冷却器出口温度悄悄冲破了历史最高值。没有人守在屏幕前——但四十秒后，一份带根因和处置建议的分析报告，已经推到了值班员手机上。

这是窑炉传感器中控台。它把全厂测点的实时数据、历史趋势、离线状态和异常事件，集中在一块屏上。数据来自 TDengine 时序库，秒级刷新。

当任意测点突破历史极值时，系统秒级判定并推送企业微信。不用刷新、不用盯盘，异常自己会找上门。

点击异常，Agent 会在后台做一轮完整分析：它先核实历史趋势判断是真异常还是毛刺，再检索知识库里的工艺文档、安全联锁和故障影响链，最后给出一份结构化的报告——结论、可能原因、处置建议、依据来源，全都写清楚，可追溯、不编造。

发现异常只是第一步。值班员在这里登记处理人和根因分类，形成完整的时间线——谁、在什么时候、因为什么、怎么处理的，一条不落。

除了异常闭环，它还提供工艺流程与异常联动、按班次和周期的自动报表，以及任意测点的历史回查。过去要导几个 Excel 的活，现在一块屏搞定。

它不只是看板，还是一个懂工艺的助手。你可以直接问它工艺问题，它会给出带文档出处的答案；也可以动口不动手，用语音问当前工况。

从秒级发现，到自动分析，再到闭环沉淀——让每一条异常都有结论、有依据、有交代。这就是窑炉传感器中控台，和它背后的智能制造全链路 Agent。

## 5. 后期制作

- **字幕**：全程硬字幕，白字 + 半透明黑底；关键词用品牌色高亮（红=异常、蓝=信息、绿=正常/已处理）。
- **BGM**：工业/科技感轻电子，音量压到旁白 -18dB 以下；镜头 1 与镜头 8 可略强，中段更低。
- **节奏**：镜头 1–3 快（制造紧张），镜头 4 慢（核心讲解），镜头 6 最快（广度）。
- **转场**：统一用 0.2s 硬切或轻微推拉，避免花哨转场。
- **封面**：`凌晨 2 点，窑温破纪录——40 秒后，报告自己来了`。
- **导出**：1080p / H.264 / 8–12 Mbps；同时导一版竖屏 9:16 用于手机传播（可选）。

## 6. 兜底方案（Demo 挂了怎么办）

1. **整段录屏兜底**：现场演示前，先按本脚本录一版完整的，存在本地，网络/模型异常时直接播放。
2. **镜头 4 重点兜底**：Agent 报告最容易慢，单独准备一张“已生成报告”的详情页截图或短录屏，随时顶上。
3. **企微推送兜底**：准备真实群消息截图，推送不通时用画中画贴图。
4. **备用事件**：准备 2–3 条已落库的极值事件，一条失败就换下一条。
5. **“重新分析”救场**：若现场某条报告为空，点「重新分析」——反手证明系统能自愈，是加分不是减分。

## 7. 录制模式 / 演示数据准备

> 目标：让 2 号冷却器出口温度「突破历史极值」的事件真实落库，且报告已生成。

**方式 A（推荐，真实链路）**
1. 确认 Agent 与中控台在线、TDengine 可写；
2. 临时向 `sensor_readings` 写入一条让带 `2#冷却器出口温度TI_809` 超过其历史上限的读数（或调低该测点基线）；
3. 等待 `EXTREME_POLL_INTERVAL_SECONDS`（默认 15s）触发 → 后台 Agent 自动分析；
4. 约 30–60 秒后，中控台「异常记录」出现该事件且已有报告 → 开始录制。

**方式 B（最稳，预生成）**
1. 提前触发一次极端事件，等报告生成后保存；
2. 录制时直接从「告警中心 → 活动/历史告警」打开一条**已带报告**的记录，按镜头 3–5 录制；
3. 镜头 3 的“实时发现”用一段预先单独录好的列表刷新短片拼接。

**方式 C（演示模式，建议 P0 补做）**
在系统里加一个「一键模拟极值突破」入口 + 种子脚本，点击后自动走完整链路。录制和现场演示都最省心（此项需单独开发，见后续任务）。

## 8. 录制顺序建议（不必按时间轴）
